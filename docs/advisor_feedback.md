## 4. Modeling Plan (start simple, then compare)

Build baselines first, then progressively more complex models:

1. **Persistence** — naive baseline (future level = current level); mandatory minimum reference.
2. **Linear / regularized regression** — using current and past rainfall + levels.
3. **ARIMA**, preferably **ARIMAX/SARIMAX** — ARIMA uses only level history; ARIMAX adds exogenous variables (rainfall, upstream levels).
4. **Random Forest / XGBoost / LightGBM** — classic ML for nonlinear relationships.
5. **LSTM** — recurrent network for temporal rainfall–level dynamics.
6. **GRU** — simpler alternative to LSTM, fewer parameters.
7. **TFT (Temporal Fusion Transformer)** — combines recurrence + attention + variable selection; can jointly predict 30/60/120 min horizons and highlight which sensors/periods matter most. **Caveat:** likely needs many flood events to train well — check the actual number/quality of usable events first, since a mostly-dry torrent may yield few despite 12 years of records.
8. **HEC-HMS** — physically-based rainfall→runoff/discharge model. Note: produces **discharge**, not water level — a level↔discharge relationship (rating curve or hydraulic model) will be needed to compare with STM08 level predictions.
9. **Hybrid model** — HEC-HMS combined with ML to correct physical-model errors.

## 5. Evaluation Requirements
Do not rely only on overall mean error (a model that always predicts low levels could look artificially good). Also evaluate:
- Peak-level error
- Peak-timing error
- Threshold-exceedance detection
- False alarm count
- Effective flood lead time / anticipation
- Standard metrics: RMSE, MAE, NSE, KGE, PBIAS
- **Per-event** results (not just aggregate)
